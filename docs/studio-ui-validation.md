# Studio responsive and mobile interaction validation

Studio shares a React DOM interface between browsers and Tauri WebViews. Responsive Chromium evidence is not native iOS/Android acceptance.

## Remote-only verification

`.github/workflows/studio-ui-audit.yml` builds isolated synthetic fixtures and runs:

- `form-audit.mjs`: inventories global settings, fixture pages, template setting groups, content libraries, editor modes and reachable shared dialogs. Two independent CI shards partition the full ordered inventory without dropping any size or surface; inspect both `studio-expanded-ui-audit-<attempt>-shard-<index>` artifacts. Each report includes the full inventory, assigned surface IDs, pending/blocked/completed coverage and actual size/gesture findings in `test-results/form-audit/report.json` and `report.md`. The 40-minute per-shard watchdog preserves partial evidence and fails on unfinished coverage. Root-modal and mocked-native complements run once, on shard 1.
- `root-modals-runner.mjs`: native HTML dialog focus containment, nested choice dialogs, creation resume and actual expired-session authentication over AI/delete dialogs. No mutation is automatically replayed after authentication.
- `native-ui.mjs`: production native adapters with a synthetic Tauri IPC host. Optional `STUDIO_TEST_GESTURES=true` collects CDP scroll/pinch observations alongside native fixture screenshots. These are not real OS locks, system gesture recognizers or WebView measurements.

For focused investigation, `.github/workflows/studio-ui-targeted.yml` runs on pushes that change its diagnostic script or workflow; once available on the default branch, it also supports manual dispatch on an exact ref. It runs a 390px synthetic-versus-dispatched touch diagnostic, root-modal/navigation regressions and the mocked-native complement in independent steps, retaining failures and artifacts without running the full six-size matrix. The diagnostic compares a static page with Studio login and a chooser, records bounded structural/input observations without form values, and does not turn a browser API acknowledgement into gesture success. Chooser setup uses fixture HTTP authentication and programmatically opens navigation/disclosures; those setup actions are not user-interaction acceptance. Dispatched pinch plans fixed root-widget geometry (`80→150` radius outward) and at most one analytically slop-compensated reverse from the measured scale. Each endpoint-only stroke sends one touch move, not a smooth human gesture. All coordinates, including the center, are inverse-mapped by the observed stroke-start page scale without visualViewport offsets; bounds are checked in the planned widget space. The report records planned widget endpoints, CDP parameters, scale/frame checks and exact Chromium source provenance. Browser zoom and embedding CSS zoom equal to one, the runtime input-feature path and browser-side ScaleFactor synchronization remain model assumptions, not directly measured facts. Unexpected scale or out-of-bounds geometry fails rather than being clamped or retried. Original synthetic helpers and thresholds remain unchanged. Cleanup tracks active/unknown touch state and records cancellation, scale reset and final geometry independently; cleanup reset never counts as gesture restoration. It is not physical-device evidence. Regular push/PR expanded audits and Studio smoke checks remain unchanged.

Do not run project installation/build/test locally. Inspect downloaded CI screenshots as well as the structured report. A blocked surface or unavailable gesture is an explicit coverage gap, not a pass. Each assigned responsive/reflow combination starts as `not-run` and is updated in place; Markdown exposes its status and error. `completedSurfaces` means collection finished, not that findings are absent. A setup-failure screenshot belongs to the surface only, never to unexecuted sizes. Expected mobile pinch without a result is `not-run`, distinct from desktop/reflow `not-applicable`.

## Shared interface contracts

- Business dialogs share an authentication-aware activation owner: pending opens cannot overtake the blocking reauthentication modal; cancellation/unmount disposes pending activation without replaying operations. The most recently activated Studio native dialog wraps Tab at its real visible-control boundaries, excludes folded disclosure contents and releases listeners on close/unmount. Native modality remains responsible for background isolation and nested-dialog focus priority.
- The app never cancels intentional pinch zoom or installs a maximum viewport scale. Text inputs have a mobile 16 CSS px floor to avoid accidental focus zoom; this is not a substitute for Dynamic Type or OS magnification testing.
- Shared touch sizing includes login, first-run screens and body portals. Native Android targets use 48 CSS px, iOS uses 44 CSS px; actual device logical-point mapping still needs device validation.
- `accessibility.css` owns common visible-viewport constraints. The visual viewport tracker also runs in browsers, so keyboard/zoom offsets can inform dialogs and save popups. Below 360 visible CSS px, dialogs fall back from fixed chrome plus inner results scrolling to one scrollable surface, keeping confirmation reachable.
- Option pickers fit short lists to content and cap long lists at the visible viewport with scrollable results; reference and OAuth panels retain their separate constraints. Compact viewports use the single-scroll fallback above. Choice dialogs separate the ordinary overflow owner from the inner semantic `fieldset`; overflow dimensions alone do not prove scrolling. Browser controls must demonstrate actual bidirectional wheel movement at desktop and phone widths, while touch/zoom keep separately labelled evidence.
- Root-modal expired-session outcomes use isolated service instances so repeated successful logins remain within the unmodified production rate limit. A login response must be HTTP 200 before testing modal removal; rejected authentication stays blocking and does not trigger a retry. The initial AI click has a separate bounded, structural-only diagnostic artifact: first-open failures precede authentication and must not be labelled as delayed-resume failures. Instrumentation may affect timing and does not itself repair an observed failure. The initial AI action requires the production button to be enabled and visible; the original editor and unsaved-draft assertions remain before input, and the opened dialog must display that draft as its model source. Its scoped Puppeteer locator explicitly requires visibility and retains default enabled, viewport and two-frame stable-bounding-box checks. Because the locator can internally retry actions, a local action listener aborts and throws before a second input action can start; a returned click must have exactly one action attempt. Readiness sampling may repeat, but failed input is not replayed. The listener is removed in the existing diagnostic finalization path. An action attempt count does not prove event delivery: trusted target and hit observations remain the input evidence. This does not wait for the whole language section to finish, force-enable a control or extend the dialog timeout. Two equal bounding boxes do not guarantee subsequent stability, lack of occlusion or unchanged inert state. Readiness and dispatch are not atomic; capture-time disabled/hit evidence governs any later failure. This changes scheduling, and a later pass cannot explain an earlier failure. Diagnostic `operation` covers only initial AI opening, not the complete outcome or suite.
- Phone form labels stack above fields rather than compressing inputs next to desktop label columns. Repeated-item actions receive a separate row. Desktop retains compact form rhythm. The shared topbar grows with wrapped translated/touch-sized controls at tablet widths as well as phones. Navigation headings keep a theme-colored visible focus cue rather than the browser's default outline.
- Navigation position is memory-only, after the existing leave guard succeeds. New destinations start at their heading; returning to the same library restores viewport context when content is ready. User input cancels queued restoration, including focus acquired by a focusable control in the destination content before the first key event; that focus must not be overtaken by a late heading placement. Navigation releases its pending ownership before performing its own heading or saved-control focus. Slow requests do not expire restoration before the destination is ready. No editor content or credentials enter history/URLs, and this does not implement browser/Android Back routing.
- Drawer navigation and the background document have different scroll contracts: an open mobile drawer locks the background while `.sidebar-navigation` scrolls independently. The broad audit's sampled document result is retained, not converted to a navigation pass. Dedicated 320×568 and 390×844 checks must observe actual bidirectional navigation movement, a stationary background, and visible/hit-testable bottom controls. Keyboard checks alone do not prove touch scrolling or logout activation. The smoke harness owns a supplemental emulation session until browser destruction; each drawer check restores its baseline through that owner, detaches a separate input-only session, and then verifies viewport, touch capability, document identity, drawer/focus and control geometry before continuing keyboard checks. This is post-restore/input-session-detach preservation, not a claim that detaching the emulation owner preserves UI state. Emulation-owner teardown is recorded separately at browser destruction; no cleanup reopens the drawer to mask lost state.
- Narrow media libraries move to the selected image details and provide a return-to-tile control; desktop keeps the side-by-side inspector. Media search occupies its own row at phone widths rather than competing with the translated refresh action. Library directories and picker filters use native disclosures, initially collapsed at widths up to 760px and expanded on desktop, with current directory/source context visible in the summary. Manual disclosure choices survive ordinary renders; crossing to the narrow layout moves focus out of content before folding it. Breakpoint callbacks synchronize the native disclosure's current open state before updating the reactive default, so an equal-value ref assignment or a queued toggle cannot preserve a divergent DOM state. A portaled nested chooser stays modal during a breakpoint change; after it closes, a trigger hidden inside a folded native disclosure returns focus to the visible summary instead of reopening the region. Dedicated short-phone checks require a meaningful loaded image preview in the initial 320×568 view, without scrolling or footer occlusion, and a fully offscreen, inert, closed navigation drawer with no backdrop. A locally hit-testable thumbnail alone does not establish a settled, unobscured screen. Upload destination and picker filters reuse compact SelectionField triggers with visible context labels and nested confirmation/cancellation; long selected paths wrap. Upload disclosure keeps the same mounted upload component, progress, per-file results/errors and immediate-save notice. Collapsing it never cancels or deletes an upload, and cancelling image selection does not undo files already saved.

### Topics setup click evidence

`form-audit/topics-initial-click.json` observes only `select-topics` setup at its existing desktop reset size, before the per-size matrix. It retains the original single topics-button click and original `ready('dialog[open]')`; it adds no enabled wait, retry, settle, forced input or production change. Textarea readiness and the absence of global `aria-busy` do not establish that the asynchronously loaded topics trigger is enabled. That source-level gap alone does not establish the cause of a particular failure.

The collector keeps the first 64 eligible capture-phase event attempts across pointer, mouse, click and focus events, 32 eligible mutation attempts, eight snapshots, and 16 failures per browser/Node context, with explicit attempt/drop counts. Dialog states are capped at eight per category (selection and reauthentication), at most 16 combined per snapshot. Numeric original/current trigger and textarea identities, connected/disabled/hidden/inert states, geometry, hit roles, viewport and selection/reauthentication dialog states are recorded; text, input values, HTML, URLs, storage and network payloads are not read. Native disabled controls may suppress some mouse/click events; missing events alone do not establish their cause. Mutation snapshots describe callback-delivery state, not historical state. Trigger replacement is detectable at snapshots/events through original/current identity, not exhaustively traced by child-list mutation records; temporary replacements between samples may be missed. Limits bound retained observations, not all observer processing work.

Installation, after-click and export RPCs introduce timing gaps. Each diagnostic RPC/write has a 10-second waiting bound, not cancellation of the underlying operation; late installation cleanup is best effort. Missing exports/cache are unavailable evidence, not zero events. Cleanup and handle disposal are independently attempted. Original click/readiness errors take priority over diagnostic errors; diagnostic unavailability after a successful operation also fails the setup and is separately identified in the diagnostic report/log. A persistence failure may only be visible in the log, since it occurs after serialization. Neither a later visible button nor an instrumented pass explains an earlier failure, and a desktop setup failure leaves all seven planned combinations blocked rather than supplying size-specific evidence.

### Media breakpoint failure evidence

In `studio.yml`, production browser smoke, React lifecycle and the historical MediaBrowser counterfactual run as separate steps after successful build/browser prerequisites. A smoke failure (including strict trace partial/unavailability) still fails the job; it does not prevent the lifecycle/counterfactual steps from collecting independent evidence. Cancellation or missing prerequisites still prevents them. Step watchdogs are 10 minutes for smoke, 5 for lifecycle, 2 for the fixed-baseline fetch and 5 for old-only checks; the 40-minute job deadline remains, so job timeout still prevents subsequent evidence. These watchdogs do not change predicate waits or permit retries. The package `test:browser` command retains its original `smoke && lifecycle` behavior. Lifecycle startup alone is not six-case coverage: each current MediaBrowser case reports PASS only after all assertions and cleanup complete, and earlier lifecycle failures can still prevent those cases from running.

The old-only runner fetches and reads `MediaBrowser.tsx` from fixed baseline `d078ced2858bafeecfd7194baf2882bb3ab3cf1a`. A fail-closed source guard requires the current component to equal that historical file plus the single breakpoint DOM synchronization line. Only the exact component module is overridden during fixture bundling, with exactly one override required; the fixture, dependencies and React bridge remain current. This is a component-level historical counterfactual, not the entire historical application or trusted-input acceptance. The runner reports baseline/checkout SHAs and each mode/direction. All six old cases must produce the sole expected `race.after` strict-equality AssertionError with the exact before-fix actual/expected values after successful cleanup. Setup errors, timeouts, other assertions, unexpected passes or any additional cleanup error fail verification, never count as expected red. Baseline fetch/read failures are infrastructure failures, not regression evidence. Current green and historical expected-red results remain separate from smoke and overall job status.

The React lifecycle regression also includes isolated MediaBrowser scheduling cases for native disclosure activation followed by a breakpoint change in the same JavaScript task, in both directions. Only the exact 760px media query is mocked; native toggle delivery, the component and React DOM remain real. These cases check immediate breakpoint reconciliation and retention through queued toggle delivery and a search render. Programmatic summary activation in this fixture is scheduling evidence, not trusted pointer/hit-test or real viewport evidence; the existing uploads smoke retains its original locator clicks, viewport changes, focus, preview, nested chooser and mounted-upload assertions.

The Studio smoke harness scopes a bounded DOM collector to the upload/media regression and writes `media-disclosure-diagnostics.json`; the report may also include the separate test-build controller trace described below. It records media-query/toggle/mutation observations, numeric node/document identity, sidebar geometry and animation state, invocation counts and first/last samples from the existing disclosure predicate, and state before/after the existing failure screenshot. It does not record form values, DOM text, URLs or raw errors. Collection limits and dropped observations are explicit: events retain the first 120 observations rather than a rolling trace. Wait `matchCount` counts successful predicate invocations, not selector cardinality; toggle snapshots describe dispatch-time DOM, not native old/new states. Screenshot checkpoints bracket the attempt, which may fail or time out without cancelling the underlying screenshot; consult the smoke errors before treating the latter checkpoint as post-completion evidence. The original rAF polling and timeout remain unchanged; no retry, extra poll or forced disclosure change is introduced. A later screenshot is not the timeout predicate's last sample, and DOM evidence cannot establish React ref state or prove a shared root cause. The collector's `outcome` describes the uploads check, not diagnostic cleanup or whole-suite success. Failed exports can leave only the last cached observations. Instrumentation may change timing; missing or truncated observations are not a pass.

The media report's schema 3 retains the schema 2 preview contract: two bounded `previewSamples`, returned by the original initial-preview `$eval` and synchronously cached in Node before its unchanged assertion. The original candidate order, `.some()` short circuit, geometry thresholds, hit-test count and final strict body-scroll-zero condition remain unchanged; no RPC, wait, rAF, reset or retry is added. The sample reuses predicate image/body/footer rectangles and hit results, retaining the first 24 visited candidates, with counts distinguishing dropped visited candidates from unvisited candidates after short circuit. The threshold is half the image CSS box's shorter side in each direction, not 50% image area or a measurement of painted `object-fit` pixels. A center hit inside the same card is a single-point check, not proof that the entire region is unobscured.

Each visited candidate also carries `imageOrdinal`, its zero-based position in the original image array, not its position in the loaded subset. After `matched`, `atSampling.mediaLayout` reads the first 24 original images' ordinals, loaded flags and rectangles, the upload disclosure's current open state and rectangle, and toolbar/filter/grid rectangles. Its `startedAt`/`finishedAt` are post-predicate `performance.now()` times. `droppedImageLayouts` counts original images omitted by that bound; null elements are unavailable/absent, not inferred closed or zero. These newly read loaded flags and boxes are not the predicate's loaded subset or rectangles and cannot retroactively establish which unloaded image was visible at predicate time. No image URL, filename, text, HTML or form value is read for this layout evidence.

`bodyScrollTopForPredicate` is null when the original short circuit did not read it, not an observed zero; a missing body retains the original true branch. Additional layout, dialog/body scroll, active-role, viewport, compact attribute and numeric CSS-variable context is read only after the original `matched` result and is explicitly labelled `atSampling`. Eight sampling faults and candidate/image-layout/sample limits have explicit dropped counts. Any dropped candidate or image layout, or sampling fault, marks the preview partial and fails diagnostic completeness, even if the original preview assertion passes. These are not atomic DOM snapshots, a scroll chronology, React state or autofocus-cause evidence. Partial/missing samples are diagnostic unavailability, not a pass; RPC failure retains the original error, and a failed preview assertion takes priority over diagnostic-record failure. Instrumentation still adds allocations and reads and can affect subsequent scheduling. Preview evidence remains synchronously cached in Node; the controller's separate segmented lifecycle and finalization are described below.

### Test-build controller / commit-phase trace

For non-release Studio verification only, the Web-build step may set `STUDIO_TEST_MEDIA_TRACE=1` with `CI=true`; the browser step separately sets `STUDIO_TEST_MEDIA_TRACE_EXPECTED=1`. The Vite plugin is dynamically imported only for that explicit CI build and rejects SSR. Release/tag/publish and native-build steps do not enable it. Normal builds do not import the virtual tracing runtime. No production component or React bridge source file is modified. The pre-transform accepts only the exact MediaBrowser source path and exact single-occurrence sentinels for controller initialization, breakpoint/toggle callbacks and the two browse-details branches; an enabled build fails if source matching, transformation or virtual-runtime loading is incomplete.

The test-only runtime observes the real breakpoint/toggle callback entry and exit, with current ref / DOM state, actual `event.matches`, and allowlisted toggle metadata. Original focus, target guard, assignments and exception propagation stay unchanged. Additional reactive reads are `untracked` to avoid adding subscriptions. Render requests retain their requested-open primitive and numeric token. Only the original summary element receives a new callback ref; details props/ref, component types, keys and mounted children remain unchanged. A non-null summary ref reports a **commit-phase attach marker**, not post-commit or complete commit. Only attach updates the last attach-observed requested-open/token; a render attempt does not. Ref detach alone is not DOM replacement, and an initial summary attach may precede the parent details ref. Callback records do not carry last-commit fields; previous attach fields occur only on attach records. The latest attach-observed state can be reconstructed only within the same controller/session when a prior attach and the necessary complete ordered records exist. Commits before session start have no baseline in this trace.

Outside the existing media diagnostic session, the runtime stops recording, but its wrappers and rest-parameter allocations remain. Its independent identity namespace must not be equated with DOM collector IDs. Runtime version 2 and report schema 3 use **one continuous logical session with eight fixed segments**, each retaining at most 256 records and 16 fixed-code faults. The explicitly authorized aggregate budget is **2048 records / 128 faults**, increased from the former single-segment budget; this is not an unchanged total cap. Numeric counters/identities are bounded at 2,147,483,647 and saturation fails integrity checks; time values are not constrained by that integer cap. Exports contain only fixed stages/codes, booleans, finite numeric IDs/times and allowlisted states, not content, paths, HTML or raw exceptions.

The fixed plan is `library-initial → library-mobile → public-picker-initial → held-upload-responsive → nested-choosers → reopened-picker → document-insert → media-source-final`. The seven boundaries use existing successful disclosure-wait exports, respectively: first library mobile collapse; first public picker collapse; collapse after held-upload/result-retention checks; expanded state after the layout/wheel loop before nested chooser checks; reopened Chinese picker expanded; document-insert picker expanded; and the media-source responsive chooser's **confirm branch desktop expanded** wait. The final segment ends at controller stop. Boundaries never depend on capacity, observed timing, retry or a global wait ordinal. This plan does not guarantee that any segment fits; an overflowing segment still fails without appending another segment.

A synchronous `rotate` in the existing export RPC seals the old segment and opens the next without stopping, restarting or changing session identity. Session-global sequence numbers, weak-map identities, captured-session ref guards and attach history continue across segments. Nonzero callback depth refuses rotation rather than waiting. Existing `await`s are not quiescence: pending render/ref/toggle work can cross the boundary, and render-request/attach/detach groups may span segments. A segment is not a self-contained commit or component lifetime. First-session preexisting commits still have an unknown baseline.

The browser keeps the current buffer; Node archives each sealed segment once and replaces its active cache rather than appending every snapshot. Rotate return values, serialization and Node validation can temporarily coexist with both buffers; the aggregate budget bounds retained logical records, not all transient copies or total process memory. Integrity checks cover owner/session/document-time identity, fixed plan and order, adjacent attempt ranges, global sequence/count continuity, caps and final inactive state. Any fault, drop, missing segment, invalid count, unavailable export or unknown continuity is sticky failure. A timed-out rotation may have already executed in the browser: it is never retried, and a later available snapshot cannot clear the lost-boundary failure.

The existing observer cleanup RPC independently attempts observer disconnect, controller stop and an inactive final snapshot; listener removal and hook deletion are also independently attempted. A pre-stop active cache is not finalization evidence. Missing final export or failed cleanup remains failure, even when uploads returned successfully; a complete successful uploads run requires all eight stages and actual stopped-final evidence. Existing install/export/cleanup RPCs carry the trace; no extra polling, timer, rAF, input, retry or production DOM write is introduced. An expected but missing/incompatible runtime is diagnostic unavailability and fails verification; an ordinary build reports tracing not enabled. Source-transform failure is a build failure, not a product finding.

This instrumentation still adds reads, allocations and ref callbacks and can change scheduling. It is not an atomic R/prop/DOM snapshot, a full React commit trace, proof of an internal DOM-diff decision, or a fix. Equal pre/post ref values plus the audited setter may identify an equal-value assignment, but absence of a later render marker does not prove absence of notification or pending work. Interpret callback / render / attach ordering together with session boundaries, missing data, faults and truncation; a later instrumented pass cannot explain an earlier failure.

## Required physical-device follow-up

Use at least one iPhone and one Android device, plus tablet portrait/landscape where supported. For every top-level page, template setting group, editor mode and dialog:

1. Scroll down and up with a finger, including over controls and inside nested lists. Confirm no scroll trap, unreachable footer or unexpected activation.
2. Pinch in and out; pan while magnified. Confirm deliberate zoom is available and actions remain reachable. Compare this with OS text sizing rather than treating it as equivalent.
3. Open the keyboard in the first and last field; rotate while editing. Confirm caret, error feedback, Cancel and Save remain accessible above the keyboard and system insets.
4. Check system Back/edge navigation, background/resume, modal dismissal and unsaved drafts. Current app navigation does not promise an OS-native history stack.
5. Repeat important flows in dark appearance, increased text size and Reduce Motion. Check VoiceOver/TalkBack labels, reading/focus order, announcements and touch exploration.

Record OS/device/build, surface, orientation, gesture and result. CI screenshots cannot establish these outcomes, physical latency or App Store/TestFlight readiness.

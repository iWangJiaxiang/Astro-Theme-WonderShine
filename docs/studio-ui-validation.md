# Studio responsive and mobile interaction validation

Studio shares a React DOM interface between browsers and Tauri WebViews. Responsive Chromium evidence is not native iOS/Android acceptance.

## Remote-only verification

`.github/workflows/studio-ui-audit.yml` builds isolated synthetic fixtures and runs:

- `form-audit.mjs`: inventories global settings, fixture pages, template setting groups, content libraries, editor modes and reachable shared dialogs. Two independent CI shards partition the full ordered inventory without dropping any size or surface; inspect both `studio-expanded-ui-audit-<attempt>-shard-<index>` artifacts. Each report includes the full inventory, assigned surface IDs, pending/blocked/completed coverage and actual size/gesture findings in `test-results/form-audit/report.json` and `report.md`. The 40-minute per-shard watchdog preserves partial evidence and fails on unfinished coverage. Root-modal and mocked-native complements run once, on shard 1.
- `root-modals-runner.mjs`: native HTML dialog focus containment, nested choice dialogs, creation resume and actual expired-session authentication over AI/delete dialogs. No mutation is automatically replayed after authentication.
- `native-ui.mjs`: production native adapters with a synthetic Tauri IPC host. Optional `STUDIO_TEST_GESTURES=true` collects CDP scroll/pinch observations alongside native fixture screenshots. These are not real OS locks, system gesture recognizers or WebView measurements.

For focused investigation, `.github/workflows/studio-ui-targeted.yml` runs on pushes that change its diagnostic script or workflow; once available on the default branch, it also supports manual dispatch on an exact ref. It runs a 390px synthetic-versus-dispatched touch diagnostic, root-modal/navigation regressions and the mocked-native complement in independent steps, retaining failures and artifacts without running the full six-size matrix. The diagnostic compares a static page with Studio login and a chooser, records bounded structural/input observations without form values, and does not turn a browser API acknowledgement into gesture success. Chooser setup uses fixture HTTP authentication and programmatically opens navigation/disclosures; those setup actions are not user-interaction acceptance. Dispatched pinch plans fixed root-widget geometry (`80→150` radius outward) and at most one analytically slop-compensated reverse from the measured scale. Each endpoint-only stroke sends one touch move, not a smooth human gesture. All coordinates, including the center, are inverse-mapped by the observed stroke-start page scale without visualViewport offsets; bounds are checked in the planned widget space. The report records planned widget endpoints, CDP parameters, scale/frame checks and exact Chromium source provenance. Browser zoom and embedding CSS zoom equal to one, the runtime input-feature path and browser-side ScaleFactor synchronization remain model assumptions, not directly measured facts. Unexpected scale or out-of-bounds geometry fails rather than being clamped or retried. Original synthetic helpers and thresholds remain unchanged. Cleanup tracks active/unknown touch state and records cancellation, scale reset and final geometry independently; cleanup reset never counts as gesture restoration. It is not physical-device evidence. Regular push/PR expanded audits and Studio smoke checks remain unchanged.

Do not run project installation/build/test locally. Inspect downloaded CI screenshots as well as the structured report. A blocked surface or unavailable gesture is an explicit coverage gap, not a pass. Each assigned responsive/reflow combination starts as `not-run` and is updated in place; Markdown exposes its status and error. `completedSurfaces` means collection finished, not that findings are absent. A setup-failure screenshot belongs to the surface only, never to unexecuted sizes. Expected mobile pinch without a result is `not-run`, distinct from desktop/reflow `not-applicable`.

## Shared interface contracts

- Business dialogs share an authentication-aware activation owner: pending opens cannot overtake the blocking reauthentication modal; cancellation/unmount disposes pending activation without replaying operations. The most recently activated Studio native dialog wraps Tab at its real visible-control boundaries, excludes folded disclosure contents and releases listeners on close/unmount. Native modality remains responsible for background isolation and nested-dialog focus priority.
- The app never cancels intentional pinch zoom or installs a maximum viewport scale. Text inputs have a mobile 16 CSS px floor to avoid accidental focus zoom; this is not a substitute for Dynamic Type or OS magnification testing.
- Shared touch sizing includes login, first-run screens and body portals. Native Android targets use 48 CSS px, iOS uses 44 CSS px; actual device logical-point mapping still needs device validation.
- `accessibility.css` owns common visible-viewport constraints. The visual viewport tracker also runs in browsers, so keyboard/zoom offsets can inform dialogs and save popups. Below 360 visible CSS px, dialogs fall back from fixed chrome plus inner results scrolling to one scrollable surface, keeping confirmation reachable.
- Option pickers fit short lists to content and cap long lists at the visible viewport with scrollable results; reference and OAuth panels retain their separate constraints. Compact viewports use the single-scroll fallback above. Choice dialogs separate the ordinary overflow owner from the inner semantic `fieldset`; overflow dimensions alone do not prove scrolling. Browser controls must demonstrate actual bidirectional wheel movement at desktop and phone widths, while touch/zoom keep separately labelled evidence.
- Root-modal expired-session outcomes use isolated service instances so repeated successful logins remain within the unmodified production rate limit. A login response must be HTTP 200 before testing modal removal; rejected authentication stays blocking and does not trigger a retry. The initial AI click has a separate bounded, structural-only diagnostic artifact: first-open failures precede authentication and must not be labelled as delayed-resume failures. Instrumentation may affect timing and does not itself repair an observed failure. The initial AI action requires the production button to be enabled and visible; the original editor and unsaved-draft assertions remain before input, and the opened dialog must display that draft as its model source. Its scoped Puppeteer locator explicitly requires visibility and retains default enabled, viewport and two-frame stable-bounding-box checks. Because the locator can internally retry actions, a local action listener aborts and throws before a second input action can start; a returned click must have exactly one action attempt. Readiness sampling may repeat, but failed input is not replayed. The listener is removed in the existing diagnostic finalization path. An action attempt count does not prove event delivery: trusted target and hit observations remain the input evidence. This does not wait for the whole language section to finish, force-enable a control or extend the dialog timeout. Two equal bounding boxes do not guarantee subsequent stability, lack of occlusion or unchanged inert state. Readiness and dispatch are not atomic; capture-time disabled/hit evidence governs any later failure. This changes scheduling, and a later pass cannot explain an earlier failure. Diagnostic `operation` covers only initial AI opening, not the complete outcome or suite.
- Phone form labels stack above fields rather than compressing inputs next to desktop label columns. Repeated-item actions receive a separate row. Desktop retains compact form rhythm. The shared topbar grows with wrapped translated/touch-sized controls at tablet widths as well as phones. Navigation headings keep a theme-colored visible focus cue rather than the browser's default outline.
- Navigation position is memory-only, after the existing leave guard succeeds. New destinations start at their heading; returning to the same library restores viewport context when content is ready. User input cancels queued restoration, including focus acquired by a focusable control in the destination content before the first key event; that focus must not be overtaken by a late heading placement. Navigation releases its pending ownership before performing its own heading or saved-control focus. Slow requests do not expire restoration before the destination is ready. No editor content or credentials enter history/URLs, and this does not implement browser/Android Back routing.
- Drawer navigation and the background document have different scroll contracts: an open mobile drawer locks the background while `.sidebar-navigation` scrolls independently. The broad audit's sampled document result is retained, not converted to a navigation pass. Dedicated 320×568 and 390×844 checks must observe actual bidirectional navigation movement, a stationary background, and visible/hit-testable bottom controls. Keyboard checks alone do not prove touch scrolling or logout activation. The smoke harness owns a supplemental emulation session until browser destruction; each drawer check restores its baseline through that owner, detaches a separate input-only session, and then verifies viewport, touch capability, document identity, drawer/focus and control geometry before continuing keyboard checks. This is post-restore/input-session-detach preservation, not a claim that detaching the emulation owner preserves UI state. Emulation-owner teardown is recorded separately at browser destruction; no cleanup reopens the drawer to mask lost state.
- Narrow media libraries move to the selected image details and provide a return-to-tile control; desktop keeps the side-by-side inspector. Media search occupies its own row at phone widths rather than competing with the translated refresh action. Library directories and picker filters use native disclosures, initially collapsed at widths up to 760px and expanded on desktop, with current directory/source context visible in the summary. Manual disclosure choices survive ordinary renders; crossing to the narrow layout moves focus out of content before folding it. Breakpoint callbacks synchronize the native disclosure's current open state before updating the reactive default, so an equal-value ref assignment or a queued toggle cannot preserve a divergent DOM state. A portaled nested chooser stays modal during a breakpoint change; after it closes, a trigger hidden inside a folded native disclosure returns focus to the visible summary instead of reopening the region. Dedicated short-phone checks require a meaningful loaded image preview in the initial 320×568 view, without scrolling or footer occlusion, and a fully offscreen, inert, closed navigation drawer with no backdrop. A locally hit-testable thumbnail alone does not establish a settled, unobscured screen. Upload destination and picker filters reuse compact SelectionField triggers with visible context labels and nested confirmation/cancellation; long selected paths wrap. Dialog triggers use explicit value and trailing slots rather than positional span selectors: single selections, including a valid empty-string option, show their matched label without a count; compact multiple selections retain their count. A decorative SVG chevron conveys expansion without changing the existing label/value accessible name. The isolated chooser fixture checks the actual shared component and stylesheet cascade at the fixed six sizes; production uploads checks separately cover the empty/nonempty single-value alignment and nested chooser semantics. This describes intended regression coverage; exact-run remote validation of the new checks is pending. These Chromium checks do not establish native IME or screen-reader acceptance. Upload disclosure keeps the same mounted upload component, progress, per-file results/errors and immediate-save notice. Collapsing it never cancels or deletes an upload, and cancelling image selection does not undo files already saved.
